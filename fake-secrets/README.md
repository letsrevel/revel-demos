# fake-secrets/ — these are FAKE. All of them. On purpose.

Nothing in this directory is a credential. Every file here was generated by
`scripts/make-fake-secrets.sh` on a laptop, is self-signed, is committed to a
public repository, and grants access to exactly nothing.

They exist so the demo environment can render Apple Wallet and Google Wallet
buttons on a ticket without anyone needing a real Apple Developer account or a
real Google Wallet issuer.

| File | Pretends to be | Committed? |
| --- | --- | --- |
| `pass.pem` / `pass-key.pem` | An Apple Wallet pass-type signing certificate and its key | yes |
| `wwdr.pem` | Apple's WWDR intermediate certificate | yes |
| `google-wallet-sa.json` | A Google Cloud service-account key | **no — generated locally** |

`google-wallet-sa.json` is the one exception. GitHub's push protection rejects
anything shaped like a Google service-account key on sight, and it does not stop
to ask whether the key is real. Rather than argue with it, the file is generated
on your machine instead: `npm install` writes it, and `bash
scripts/make-fake-secrets.sh` regenerates it any time. If it happens to be
missing, the wallet buttons still appear — the app decides that from its
settings, not from the files — only clicking one would fail.

Two things follow from them being fake:

- Passes generated with them are **not valid**. Apple Wallet and Google Wallet
  will refuse them. The buttons are there to be *filmed*, not to be used.
- **Never point a real deployment at this directory.** If you are configuring
  anything other than a throwaway demo box, stop.

Regenerate them any time with `bash scripts/make-fake-secrets.sh`.
